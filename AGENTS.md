# web/AGENTS.md

Marketing site + docs portal for OpenClip (a macOS app; the rest of the repo is Swift). Standalone Next.js app, built as a **static export** (`output: "export"` → `out/`) and served by Cloudflare Workers Static Assets, with a small `worker.ts` for the few dynamic routes.

## Stack & commands

- Next.js 16.4.5 (App Router), React 19, TypeScript strict, Tailwind CSS v4, `lucide-react` icons. Package manager is **bun** (`bun.lock`). No test suite.
- `bun dev` (http://localhost:3000) · `bun run lint` · `bun run build` (prebuild sync scripts + `next build` → `out/`) · `bun run preview` / `bun run start` (build, then `wrangler dev` on :8787 with the Worker) · `bun run deploy`
- **Next 16 is newer than most training data — before writing Next-specific code, read the bundled docs in `node_modules/next/dist/docs/` and heed deprecation notices.**
- Deployed on **Cloudflare Workers** (`wrangler.jsonc`); there is no OpenNext or Vercel config. Workers Builds must run `bun run build` then `npx wrangler deploy` (previews: `npx wrangler versions upload`). `next dev` serves pages only: the dynamic routes live in `worker.ts`, so use `bun run preview` to exercise `/api/*` and `/download`, and to check headers/redirects.
- Every page is prerendered at build time and served as a file by Static Assets (HTML, RSC `.txt` payloads, metadata images), so **a page is as fresh as the last deploy** and page views never run Worker code. Anything that needs a request at runtime (`export const revalidate`, `cookies()`, `searchParams`, dynamic route handlers, `dynamicParams: true`) fails the export build — put it in `worker.ts` instead. Headers live in `public/_headers` and redirects in `public/_redirects` (`next.config.ts` `headers()`/`redirects()` are not supported by a static export); a page using `redirect()`/`permanentRedirect()` also needs a `_redirects` line.

## Layout

- `src/app/page.tsx` — marketing homepage. Showcase cards reference `/gifs/*.gif` / `*.mp4`, auto-converted to hardware-accelerated MP4s at build time via `scripts/convert-gifs.ts`; `GifFrame` renders a "Drop into /public/gifs/" placeholder until you add them.
- `src/app/extensions/page.tsx` + `src/app/extensions/[id]/page.tsx` — extension store, prerendered from the baked catalog (`readBakedCatalog()` in `src/lib/extensions.ts`); `[id]` pages have per-extension metadata, and unknown ids get the static 404 page. Install is an `openclip://install?id=…&name=…&url=…` deep link.
- Extensions data: `scripts/build-extensions-api.ts` (prebuild, after `sync-extensions`) fetches `catalog.json`, `extension-stats.json` and `featured.json` from `ganeshmshetty/openclip-extensions`, downloads any icon missing from `public/icons/extensions`, and writes `public/_api/extensions/` (`catalog.json` for the pages and search, plus `limit-{12,50,500}/page-N.json`). The build **fails** if the catalog or stats can't be fetched — never bake zeroed counts or an empty store. `worker.ts` + `src/worker/*` serve `GET /api/v1/extensions` (prebuilt file, or search over the baked catalog cached in the Cache API under a per-deploy key), `GET /api/v1/icon/:id` (baked icon, upstream fallback), and `GET /download` (latest-release redirect). `run_worker_first` in `wrangler.jsonc` lists those paths; everything else is a static file.
- `src/app/docs/[slug]/page.tsx` — docs portal. `/docs` and `/help` are static 301s to `/docs/getting-started` in `public/_redirects` (not available under `next dev`).
- The navbar's GitHub star count is baked in at build time by `scripts/sync-stars.ts` → `src/lib/github-stars.json` (last committed value is the fallback); `/api/v1/stars` is prerendered from the same file.
- The docs portal is **markdown-ingested directly from the repository's `docs/` folder**: `scripts/sync-docs.ts` runs at `predev`/`prebuild` to extract all markdown docs into `src/docs/data/docsData.json`, parsed and rendered natively via `MarkdownRenderer.tsx` and registered in `src/docs/registry.ts`. Add or edit `.md` files in `docs/` and the website picks them up automatically with zero double-maintenance. Each doc is statically generated at `/docs/<slug>` with per-doc canonical metadata, JSON-LD structured data (`TechArticle` and `BreadcrumbList`), and dynamic TOC.
- The extensions store is **prerendered at build time** from the build-time catalog: `src/lib/extensions.ts` fetches/caches the live catalog (with the committed snapshot as an offline fallback), `generateStaticParams` bakes every id the sitemap advertises, and `/extensions` + `/extensions/[id]` publish metadata, canonical URLs, and real 404s for unknown ids. A catalog entry published *after* a deploy is a static 404 until the next sync deploy rebuilds it; no request ever triggers Worker-side HTML rendering.
- Repository `docs/` is the single source of truth for documentation.

## Conventions

- Theme via CSS variables in `src/app/globals.css` (`:root` = light, `[data-theme="dark"]` = dark). Use `var(--bg-*)`, `var(--text-*)`, `var(--accent)`, `var(--border-*)` — never hardcode colors. Theme persists under `openclip-theme` in localStorage; the inline script in `layout.tsx` `<head>` prevents flash.
- Reuse the Apple-style component classes in `globals.css` (`nav-pill`, `glass-card`, `mac-window`, `btn-primary`, …) and arbitrary-value Tailwind (`text-[13px]`). Shared UI lives in `src/app/components/`.
- Marketing copy guidance lives in `.agents/product-marketing.md` (voice, positioning, words to use/avoid).
- SEO lives in `layout.tsx` (metadata + JSON-LD), `sitemap.ts`, `robots.ts` (disallows `/api/`). Base URL = `NEXT_PUBLIC_SITE_URL` env, falls back to `https://www.getopenclip.app`.
